# SearchLauncher 0.1.6: keyboard keeps up with fast typing

## What changed

- **Fast taps are no longer dropped.** Typing quickly with two thumbs on the built-in keyboard used to lose letters. Each finger is now its own press: overlapping taps on different keys are typed in the order they went down, and two fingers on the same key type it twice. A key you are still holding no longer opens its accent picker when the next finger lands.
- **No more dead zones.** Each key now owns half of the gap around it, and the outer keys of the middle row also cover the indent beside them. The keyboard looks the same.
- **Drift is tolerated.** A tap may roll up to 16dp, even past the edge of its key, and still types. A longer drag types nothing, so Go never opens from a drag.
- **Gestures leave taps alone.** Keyboard swipes (cursor, result scrolling, home gestures) now start at 16dp instead of the platform's 8dp, so a slightly moving tap types its letter instead of being swallowed.

Includes [PR #202](https://github.com/ontola/searchlauncher/pull/202).

## Updating

Same signing as 0.1.5. The GitHub `app-play.apk` uses the Google Play identity; the legacy `app-release.apk` keeps its separate signature and the WebView engine.

## Validation

The change passed CI (build and unit tests), including a new Robolectric test with 10 multi-touch, gap and drift cases. The debug build was tried by hand on a Xiaomi 15 and a Galaxy Tab S9+. The instrumented keyboard tests were run on the Galaxy Tab S9+ against an earlier commit of the PR, not against the final version.
