# SearchLauncher 0.1.1 — smoother keyboard transitions and fewer tab reloads

## What changed

- **Less jumping when typing on websites.** The browser now resizes the page once when the keyboard opens or closes, and changes toolbar visibility at the same moment. This reduces repeated movement of bottom navigation bars and avoids resizing Gecko on every keyboard animation frame.
- **A clearer bottom bar.** A subtle 1px line separates browser controls from the page, using a light or dark tint that follows the bar's colors.
- **Tabs stay open through more settings changes.** Switching dark mode, language, font size or display settings no longer unnecessarily reloads normal browser tabs. Favorite sites and installed web apps are kept ahead of other tabs when deciding which pages to reclaim; Android can still stop them under memory pressure.
- **Browser startup reliability.** Fixed an optimized-build crash involving Gecko's debug configuration parser and disabled that debug-file feature in production.
- **More useful diagnostics.** Feedback reports include tab-reload reasons and the most recent available main-thread ANR stack to help diagnose remaining freezes and reloads.

## Updating

This is an update to the regular SearchLauncher app. No data reset is needed when updating from 0.1.0. If upgrading directly from a WebView-era release, launcher settings, favorites and bookmarks are preserved, but website cookies and site sessions do not migrate to Gecko.

The keyboard regression was reproduced on a plain fixed-footer page: three opening/closing cycles produced 31 viewport-height changes in 0.1.0 and six after the fix. These are emulator measurements, not a claim of verified Xiaomi frame rates.

Remote background Web Push and credential-provider passkey restrictions remain unchanged from 0.1.0.
