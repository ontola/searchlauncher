# SearchLauncher 0.1.8: report pages that stop responding

## What changed

- **"This page isn't responding."** When a page in the built-in browser (Gecko) has been on screen for 3 seconds without drawing (10 seconds while it is still loading), a bar appears over it with Reload and Report. Until now such a page just showed its blurry saved preview and ignored touch. Each time, a warning with the page's engine state and only the site's host goes to Sentry, when crash reporting is on.
- **Report a problem.** A new entry in the browser menu, also behind the bar's Report button, sends a report with an optional message. The page address and the browser state can each be left out. Device and app version are always included.
- **Search results.** The previous query's results no longer stay drawn over the new ones while typing fast.
- **Readable crash reports.** Play builds now upload their R8 mapping to Sentry, so reported stack traces show the app's real class and method names.

The F-Droid / legacy WebView build gets the search fix only.

Includes [PR #215](https://github.com/ontola/searchlauncher/pull/215) and [PR #221](https://github.com/ontola/searchlauncher/pull/221).

## Updating

Same signing as 0.1.7. The GitHub `app-play.apk` uses the Google Play identity; the legacy `app-release.apk` keeps its separate signature and the WebView engine.

## Validation

CI passed (build and unit tests). The not-responding bar has not yet been seen on a device.
