# SearchLauncher v0.0.42

## Add Shelter shortcuts and launch work-profile apps

SearchLauncher now accepts Android’s “Add shortcut” requests. This addresses the missing launcher support that caused Shelter to report that it could not add shortcuts. Confirm **Add** to put the shortcut in your favorites.

- Personal and work-profile copies of an app appear as separate search results.
- Work apps have a **Work profile** label and a badged icon.
- Apps and shortcuts open in their original profile, including from saved favorites after restarting SearchLauncher.
- Existing personal-profile favorites keep working. If a work profile has been removed, its saved items will not open the personal copy instead.

## Try it

Install the release APK below and make sure SearchLauncher is your default launcher. In Shelter, try creating a shortcut for a cloned app, accept the confirmation, and open it from SearchLauncher’s favorites. You can also search for the cloned app directly.

Please report whether this resolves the problem in [#131](https://github.com/ontola/searchlauncher/issues/131), including your Android version if it still fails.

## Validation

Debug and release unit suites passed (352 tests per variant, with three existing skips each). On an Android 15 emulator, a separate test publisher successfully added personal and work-profile shortcuts, and both apps and pinned favorites opened in the correct profile. Cancellation and invalid-request checks passed. The original Shelter flow still needs confirmation on a real device.

This APK updates the regular GitHub-release installation of SearchLauncher. It does not update the separately installed debug/preview app.
