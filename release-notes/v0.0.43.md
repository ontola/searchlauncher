# SearchLauncher v0.0.43

## Treat favorited sites as apps

A pinned website now behaves like an app favorite: one icon per site, and tapping it resumes a tab already open on that host instead of opening the start URL again.

- Site identity is the host, with a leading `www.` stripped. Subdomains stay distinct.
- Pin a site by long-pressing a tab and choosing **Add to Favorites**, or by dragging the tab onto the favorites strip. Both write a bookmark for the current URL and pin that bookmark.
- Tapping a pinned bookmark resumes the active tab on that site if there is one, otherwise the newest, and leaves its current URL alone.
- Recents hide extra tabs and history for a pinned site, the same way a pinned app leaves the recents strip.
- The browser menu has **Add site to Favorites** / **Remove site from Favorites**.
- Settings → Browser → **Treat favorited sites as apps** (on by default). Off restores exact-URL pins.

## Try it

Install the release APK below and make sure SearchLauncher is your default launcher. Open a site in the browser, pin it from the tab or the browser menu, then tap the favorite on the home screen — it should resume the same tab. Extra pages on that site should leave the recents strip.

## Validation

`./gradlew spotlessCheck test` passed on the feature branch. Unit tests cover host normalization, collapse/dedupe, recents filtering, site-tab picking, drag/pin plans, repository pin/unpin, and ResultLauncher resume vs exact-page open. On an AOSP Android 30 emulator, pinning example.com from the browser menu created one favorite and tapping it resumed the existing tab.

This APK updates the regular GitHub-release installation of SearchLauncher. It does not update the separately installed debug/preview app.
